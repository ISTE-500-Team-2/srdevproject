# Build the ARBOR Database Overview

Edit [the Markdown source](../SPONSOR-DATABASE-OVERVIEW.md) and, when needed,
[the account relationship diagram](../assets/database-account-map.svg).
The Word and PDF files are generated companions of that source.

## Requirements and command

Use the repository's supported Node.js version (see the root `package.json`)
and an installed Google Chrome, Chromium, or Microsoft Edge executable.
No npm packages, database connection, network access, or Word installation are
needed. The build does not run application or database tests.

From the repository root:

```sh
node docs/print/build-database-overview.mjs
```

The builder detects common browser installation paths on Windows, macOS, and
Linux. To select another executable, set `CHROME_BIN` before running it:

```powershell
$env:CHROME_BIN = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
node docs/print/build-database-overview.mjs
```

```sh
CHROME_BIN=/usr/bin/chromium node docs/print/build-database-overview.mjs
```

The browser uses a separate temporary profile that is removed after the build.
Close an output file in Word or your PDF viewer if it prevents replacement.

## Generated files

- `ARBOR-Database-Overview.docx`: editable Word document with headings, tables,
  the embedded diagram, clickable citations, repository links, and page numbers.
- `ARBOR-Database-Overview.pdf`: printable copy generated by the browser.
- `ARBOR-Database-Overview.html`: self-contained browser preview and PDF input.

Relative Markdown links become clickable GitHub links in the generated files.
They point to `main` by default and require repository access. New or revised
targets become available there after the documentation is published. For an
archived release, set `ARBOR_DOCS_REF` to a published commit or tag containing all
referenced files, then rebuild; record that value with the delivered copies.
The Markdown links continue to work within a local repository checkout.

## Review after regeneration

1. Open the Word and PDF copies. Check table wrapping, diagram labels, page
   breaks, and the final references page; Word pagination may differ from PDF.
2. Follow a numbered citation and a repository link in each format.
3. Confirm the source date, migration transaction boundaries, operational links,
   and dated evidence match the selected release. Keep unfinished sponsor/server
   and physical-reader acceptance explicit.
4. Commit the source, diagram, builder, and generated companions together.

The builder supports the headings, paragraphs, bold text, inline code, links,
lists, tables, image, code block, and explicit page breaks used by this overview.
Extend the builder before introducing other Markdown constructs.
