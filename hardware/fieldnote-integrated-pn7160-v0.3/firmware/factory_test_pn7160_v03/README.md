# PN7160 v0.3 factory diagnostic

This separate, read-only NFC image tests GPIO1 green, GPIO3 amber and GPIO10 red individually or together while PN7160 discovery and Wi-Fi continue. The original product and v0.2 files are preserved. Physical tests remain **NOT TESTED / production HOLD**. Follow [factory-test-PN7160.md](../../manufacturing/factory-test-PN7160.md).

It copies the verified product's `pn7160_nci.h`, `pn7160_arduino.h` and `integrated_power.h` exactly; the factory manifest records source correspondence. PN7160A1HN/C100E uses GPIO7 active-HIGH VEN, GPIO20 active-HIGH IRQ, GPIO4/5 I²C at 100 kHz and seven-bit address 0x28. R27 is fitted, R28 DNP. Never fit both; ROM UART recovery requires removing R27 before fitting R28 and holding VEN LOW. Native USB GPIO18/19 needs **CDCOnBoot=cdc**; CDC-off compilation is rejected.

Default/unattached GPIO6 HIGH holds VEN LOW, Wi-Fi off, CPU 80 MHz and only amber lit. The independent priority-3 supervisor requires 100 ms continuous GPIO6 LOW before full startup and observes downgrade every nominal 10 ms without waiting for the NFC mutex. Hardware USB100 limiting is independent; the software period is not measured shutdown latency. Initial VEN reset/cold-start/NCI setup precedes Wi-Fi AP startup; actual RF polling waits for the AP. Reader retries can occur with Wi-Fi live, which requires a separate inrush measurement. Power loss aborts transport and clears LED stress mode during service cleanup.

On a qualified source, connect to **Fieldnote-Test-<six hex digits>**, password **fieldnote-test**, and open **http://192.168.4.1/**. Use the green/amber/red buttons for at least five seconds each, confirming only the selected optical path lights. Select **All three: stress** and keep the page open: it makes uncached status requests once/second and continuously fetches fixed 4 KiB payloads from `/api/load`, while the separate NFC task continues selecting real cards. Other LED buttons stop that browser traffic. Record client throughput and delivered-byte totals; server `load_bytes_offered` counts attempted responses and does not prove delivered throughput or worst-case radio consumption. `/api/status` reports `led_mode`, `reader_ready`, exact UID/protocol, scan/detection/request/traffic counters, uptime, controller model/version and power state. `/health` returns 503 for an unavailable reader. This image never authenticates or writes tag memory and does not store Wi-Fi credentials.

The equivalent control is `POST /api/led` with form field `mode=green|amber|red|all|off|auto`. A lost power qualification rejects control with 503 and restores service LEDs. `/api/load` requires qualified power and All mode both before building its payload and before sending. The page stops its load loop on an HTTP error, network failure or status showing service/another LED mode. After requalification, reconnect to the AP and select stress again; status polling/recovery never resumes load automatically. Alternate known cards during the ten-minute/both-orientation procedure and require increasing scan/request counts, correct UIDs and measured power/RF limits. Missing-tag polling remains a normal healthy outcome; a controller failure requests one immediate reset/reinit, then failed bring-up retries after 30 seconds.

Build with ESP32 Arduino **3.3.12** and ArduinoJson **7.4.3**:

```sh
arduino-cli compile --fqbn esp32:esp32:esp32c3:CDCOnBoot=cdc --export-binaries .
```

The saved [factory-build-manifest.json](../factory-build-manifest.json) records exact hashes and image offsets. For the identified native USB port, the compiled separate images use bootloader **0x0**, partitions **0x8000**, `boot_app0.bin` **0xE000**, application **0x10000**; alternatively the merged image starts at **0x0** on fresh first articles. Use separate images to preserve existing NVS/credentials; a merged fresh-board image can overwrite that region. Do not mix files from the product/factory manifests. The diagnostic is intended for first articles; use the separate product image for confirmation/NDEF/Classic/write/rollback acceptance. No device is flashed while preparing these files.
